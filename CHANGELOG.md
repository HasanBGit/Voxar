# Changelog

## 0.0.1 (unreleased)
- Project scaffold: license files, third-party license and data tracking, package skeleton. No functional code.
- Foundations (P0): ruff, mypy (strict), pytest with an 85% coverage gate, pre-commit (ruff, gitleaks, large-file check), uv lockfile.
- CI: lint, type check, test matrix (Linux/macOS/Windows, Python 3.10/3.12), runtime-dependency license audit (fails on GPL/AGPL/unknown), security scan (gitleaks, pip-audit, semgrep), CodeQL, Scorecard, dependency review, Dependabot. Actions pinned by commit SHA.
- Release workflow: tag-triggered build, SBOM, build-provenance attestation, PyPI Trusted Publishing behind a manual approval environment.
- Docs: ARCHITECTURE.md, ADRs 0001-0003, draft threat model.
- Core library (P1), test-first and without any real model: domain types and one error hierarchy, `SpeechRecognizer`/`SpeechSynthesizer` ports, engine registry (explicit and entry points, lazy), `Config` from environment, model store with pinned SHA-256 and atomic verified install, WAV handling and chunking, `Voxar` facade, `voxar` CLI (`transcribe`, `say`, `models list|verify`, `doctor`). 78 tests, 99% coverage, mypy strict, ruff clean.
- Fixed in CI before first run: the license audit used exact-string matching and would have missed `GNU General Public License v3 or later (GPLv3+)`; it now fails on any license containing "GPL" or "UNKNOWN" (verified against a real GPL package).
- First real engine (P2): Moonshine streaming Arabic ASR adapter (`voxar[moonshine]`, entry point `voxar.recognizers`), `voxar models pull` (HTTPS only, license acknowledgement flag, hash-verified atomic install, idempotent), `voxar listen` (microphone), real catalog entry with measured SHA-256 values, opt-in integration tests. 106 unit tests plus 3 integration tests; 98% coverage.
- Verified end to end on one synthetic Arabic (macOS voice) sample: pull, verify and transcribe work. Not measured: accuracy on real or Saudi speech, speed, live microphone capture.
- Known open issue: license of the Moonshine Arabic CDN artifact is unconfirmed (see THIRD_PARTY_LICENSES.md).
- Saudi TTS plugin (P3), GPL-3.0-only, separate project `plugins/voxar-tts-espeak`: `nabra-saudi` synthesizer (Nabra-Saudi-7M, voice `af_msa`, 24 kHz) discovered through the `voxar.synthesizers` entry point; pure synthesis logic (sentence splitting, 510-phoneme limit, pauses, PCM) unit-tested without torch; reviewed Nabra code vendored with network fallbacks removed, notices, and a hash manifest enforced by a test; opt-in integration tests. 16 unit + 3 integration tests.
- Core additions for it: `nabra-saudi-7m` catalog entry (pinned commit and SHA-256), HTTPS-only redirect handling in downloads, `voxar.testing` (shared engine contracts plugins reuse).
- Verified: pull through Hugging Face's CDN redirect, then a Saudi-dialect sentence synthesized and transcribed back by the Moonshine ASR to the same text (one sentence; not a quality measurement). `pip-audit` clean on the plugin environment.
- Agent and app layer (P4): `voxar mcp` (MCP server over stdio, extra `voxar[mcp]`; tools `transcribe_file`, `speak`, `list_engines`; paths confined to `--allow-dir`, no overwrite by default) and `voxar serve` (local FastAPI server, extra `voxar[server]`: `POST /v1/transcribe`, `POST /v1/speak`, live `WS /v1/stream`; loopback-only unless `--allow-remote`; Host/Origin guard against DNS rebinding; upload/stream/concurrency limits). `Voxar.transcribe_audio`, `read_wav_bytes`, file-like `write_wav`.
- Verified against real processes: MCP over real stdio with a real MCP client (ASR and, in the plugin environment, Saudi TTS), and the real server with curl and a real WebSocket client streaming the Arabic sample (partials grew, then a final event; spoofed Host got 403, foreign Origin refused). 149 core unit tests, 98% coverage.
- Not done: authentication, HTTPS, browser demo.
- Model reuse: the Moonshine adapter now loads the model once and gives every `stream()` call its own stream (Moonshine documents its API as thread-safe with work on one transcriber serialized). Verified on the real model: 1 sequential + 4 concurrent streams caused exactly one model load, and all results were identical. Not timed.
- Release prep (P5, local): wheels and sdists build and pass `twine check`; clean-venv install of the wheel works on Python 3.12; SBOM generated from the installed wheel with all extras (43 components, no dev tools); `scripts/check_dist.py` fails builds with missing license files or metadata (tested with a deliberately broken wheel). Fixed along the way: the plugin wheel did not ship the Apache-2.0/MIT texts of its vendored code (now `license-files`, SPDX license expressions in both projects); the release workflow's SBOM described the dev environment and wrote into `dist/` (now separate, from the installed wheel); a YAML error in the release workflow (an unquoted `: `).
- Single source of truth for the version (`__version__`; `pyproject.toml` reads it) in both projects.
- Docs site (mkdocs-material, `mkdocs build --strict` in CI, 15 pages), RELEASING.md, SUPPORT.md, issue and PR templates. Repo tests guard the CI files (valid YAML, actions pinned to SHAs, no untrusted event data in `run:` steps, manual approval before publish).
- Not done: the release workflow has never run (no GitHub remote); the plugin is not covered by it; no docs hosting workflow; no demo recording.
- README rewritten on the Graphify README's structure (centered header, language switcher, badges, one-line pitch, bullets, "get started", "see it in action" with real output, capability table, install/extras tables, MCP and server usage, environment variables, privacy, troubleshooting, command reference, licensing), but with only true content: no logo, no badges or links for things that do not exist, and "What is and isn't verified" instead of a benchmark table. Added an Arabic README (`docs/translations/README.ar-SA.md`). Tests check that README commands parse against the real CLI, links resolve, Arabic code blocks match English ones, and no nonexistent-service links appear.
- Server: live WebSocket streams are now limited (4 at once; a fifth is closed with code 1013), closing the gap where only HTTP jobs were bounded. Docs and threat model corrected.
- Measured performance and load (owner asked for real numbers; the earlier "no benchmarks" rule is lifted for speed and load): `scripts/benchmark.py` (speed, memory, WER/CER) and `scripts/loadtest.py` (HTTP and WebSocket load), full results and methodology in `docs/performance.md`. On an Apple M4 (10 cores, CPU only): speech-to-text about 18x real time on short clips, 23-32x on long audio; text-to-speech about 30x; whole-process `voxar transcribe` of a 4 s clip 0.28 s; server about 7 requests/s. Accuracy was measured only on synthetic audio (8 MSA sentences WER 4.1 %, CER 0.7 %; 4 dialect-worded sentences read by an MSA voice WER 29 %, CER 5 %), so it is a smoke test, not a benchmark.
- Changes driven by the measurements: (1) the server runs one inference job per engine at a time, with a bounded queue (8) and an immediate `503` + `Retry-After: 1` beyond it, because concurrent jobs on one model were about 30 % slower in total and a second model instance did not scale; (2) `transcribe` uses 100 ms chunks up to 15 s and 2 s chunks beyond (1.5-3x faster on long audio at equal accuracy; short clips need the fine chunks), an explicit `chunk_ms` always wins; (3) WebSocket capacity refusals now accept, send an error message and close with 1013 (a real client previously saw a bare HTTP 403); (4) Moonshine's native tokenizer warning on every start is held back during model load and shown only if loading fails. Whole-file mode and a model pool were tested and not adopted (reasons in `docs/performance.md`).
- Browser test page served by `voxar serve` at `/` (`voxar/ui/index.html`, single file, no build step): record or upload audio to transcribe, type text to hear the Saudi voice, engine status, copy and download buttons, dark mode, phone layout. Layout, tokens and fonts follow nabrah.ai's published CSS (Satoshi, Inter, Instrument Serif, Tajawal; light and dark palettes), not its text, logo or images. Audio is converted to 16 kHz mono WAV in the browser. Verified by driving the real page in headless Edge over the DevTools protocol: upload, text-to-speech playback (4.1 s of audio), the empty-text error, and a screenshot review at 1280 px and 390 px. Known limit: after capture from Chrome's fake microphone in headless mode, conversion sometimes takes tens of seconds (the result still arrives); five consecutive uploads never stalled. Real microphone untested. Conversion has a 20 s timeout and requests a 3 min timeout so the page never waits forever.
- Live mode in the test page: `Start live` captures the microphone with an AudioWorklet at 16 kHz and streams 100 ms frames to `WS /v1/stream`; partial text (grey) updates in place and final lines lock in; `Stream a file as live` plays any audio file through the same path paced at real time (usable for demos and tests without a microphone). Handles Stop mid-stream, a closed or refused connection, and the server's 4-stream limit (shows its message). Verified in headless Edge on the real server: a 5.7 s clip streamed live gave first text at 1.0-1.3 s, visible revisions and the correct final line; Stop kept the text so far and returned to idle; fake-microphone live streamed 3.8-4.0 s of audio and ended cleanly; a fifth stream showed "too many live streams". A page test runs `node --check` on the page's JavaScript (caught a deliberately introduced typo). Not verified: a real microphone.
- Test page redesigned for clarity and speed (owner asked for a better, faster UI/UX): one **Listen** stage that live, dropped files and results all write into (Copy, Clear), a single way to use the microphone with a live level meter, timer and first-text latency (the flaky one-shot Record button is removed), drag-and-drop files transcribed at once with an optional "play as live", Space to start and stop, a **Speak** panel with three one-click sample sentences, Ctrl/Cmd+Enter, Download WAV, a newer Speak request cancelling an older one, and both tools above the fold at 1280x900. Fonts no longer block rendering: median first contentful paint 548 ms to 56 ms (5 loads each, headless Edge, real network). `voxar serve` warms the engines in the background (`--no-warm` to opt out): first Speak after start-up 0.14-0.20 s instead of about 3.0 s over 3 fresh starts each, at the cost of about 270 MB resident memory until first use. Verified by a 16-check browser script against the real server: 16 of 16 passed. Real microphone untested.
